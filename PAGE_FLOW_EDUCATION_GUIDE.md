# 📚 Complete Page Flow & Architecture Education Guide

## System Overview

The Muslim Welfare AI System is a research data collection platform with 10 interconnected pages. All pages follow a **hub-and-spoke navigation model** where the Home page is the center, and users can navigate to any page in one click.

---

## 🎯 7 Core User Journeys

### Journey 1: Create & Manage Research Projects
**Page:** Projects (`/projects`)

1. User navigates to Projects page
2. Clicks "Create New Project" 
3. Fills form: Title, Description, Budget, Dates
4. Frontend sends: `POST /api/projects`
5. Backend stores in `research_projects` table
6. Project appears in list
7. User can add Phases and Budgets to project

**Data Flow:** Form Input → API → Database → List Display

---

### Journey 2: Collect Household Data (MOST IMPORTANT)
**Page:** Survey (`/survey`)

#### Option A: Manual Entry
1. Enter household name, address, phone
2. Add family members one by one
3. Review and submit
4. Backend: `POST /api/survey`
5. Data stored in `households` and `household_members` tables

#### Option B: AI Auto-Fill (NOW WORKING!)
1. Enter household name only
2. Click "Auto-Fill with AI"
3. Frontend sends: `POST /api/agents/auto-fill`
4. Backend generates realistic data:
   - Uses Claude AI if API key is set
   - Uses demo templates if not (Hassan/Khan/Ahmed families)
5. Form auto-populates with 4-5 family members
6. User reviews and submits
7. Data saved to database

**Demo Data Included:**
- Hassan Family (Chennai, Tamil Nadu)
- Khan Family (Coimbatore, Tamil Nadu)  
- Ahmed Family (Madurai, Tamil Nadu)

---

## 🔌 Complete Architecture

```
USER BROWSER
    ↓
FRONTEND (React/Next.js)
    ├─ Renders pages
    ├─ Collects user input
    ├─ Sends HTTP requests to backend
    └─ Displays JSON responses
    ↓
BACKEND (Cloudflare Workers)
    ├─ Receives HTTP requests
    ├─ Validates data
    ├─ Processes business logic
    ├─ Queries/updates database
    └─ Sends JSON responses
    ↓
DATABASE (D1 SQLite)
    ├─ research_projects
    ├─ study_phases
    ├─ project_budgets
    ├─ researchers
    ├─ project_researchers
    ├─ consent_forms
    ├─ irb_submissions
    ├─ data_access_logs
    └─ (3 more tables)
```

## 🔐 Security & Permissions

**7 User Roles:**
- super_admin: Full system access
- research_admin: Project management
- principal_investigator: Own project access
- co_investigator: Limited access
- data_analyst: View & analyze
- enumerator: Data entry only
- auditor: View-only logs

**Permission Flow:**
1. User makes request with auth token
2. Backend checks role + action + resource
3. Allows or denies access
4. Logs action in audit trail
